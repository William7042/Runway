receipt = execute(proposal['id'])

- `RUNWAY_MODE=stub` (default): canned NVDAc simulation, with explicit simulation flags and null transaction hash. `StubRouter(queue=..., on_chain_price=120, reference_price=100)` demonstrates drift fallback to USDC. Update `on_chain_price` or `reference_price` from the UI slider.

## Routing, treasury and wallets

`PaymentRouter` enumerates held assets and registered seller assets on matching chains. It compares pay-in-kind with stablecoin/token swap-then-transfer paths, quotes candidates, bounds cost against an injectable independent reference price, and returns ranked alternatives with rejection reasons. Unknown recipients, unsupported chains/venues, unknown prices, bridge mismatches, insufficient holdings, excessive impact and excessive stock drift stop the route. Nonstable-to-nonstable swaps are not supported in this demo.

Reference prices use CoinGecko's free simple-price API with a catalog slug; missing or stale data rejects the path. A configured tokenized stock `reference_symbol` uses Yahoo's free chart endpoint with a freshness bound. Providers and slider values can be injected. Stablecoins explicitly assume $1 for this demo; that assumption is surfaced in flags. Production stock checks need a licensed, session-aware reference source.

Treasury modes are configured per buyer in `modes`:

- `pay_in_kind`: use the lowest-cost supported path; an accepted holding avoids a swap.
- `endowment`: weighted-average remaining basis from complete, reconciled normalized acquisition history; payment plus cost cannot exceed unrealized gains. **The current account's legacy history lacks acquisition USD values and fees, so live endowment fails closed.** Deposit value is never guessed as zero basis. `remaining_basis` and `spendable_gains` support injected complete histories.
- `auto_top_up`: pay from stablecoin, then create separate **pending** buy-back proposals toward `top_up_targets`. Each target contains `asset_id`, `weight` (0–1), and `limit_price`. Only an approved proposal can place its limit order. Current live buy-back support is CeFi only; the test user's on-chain PYUSD does not establish CeFi funding/access. Unsupported venues reject; there is no market-order fallback. Resting orders return status `approved` until a later `execute(id)` observes a terminal fill.

Add `asset_metadata: {ASSET_ID: {reference_symbol: 'NVDA'}}` to account config for actual tokenized stocks discovered in a future catalog. This annotates a real asset; it cannot invent a tradable NVDAc listing.

`router.create_wallet(name)` creates a Gateway user with Solana and EVM wallets and a locally persisted signer, because this organization credential uses Gateway onboarding. The legacy SDK `defi.create_wallet` is for a different auth flow. In dry run no user or signer is created. `propose_funding`, `propose_payout`, and `propose_refund` all use the same payment proposal and execution gate. Register recipients and their accepted catalog asset IDs before use. Escrow is app-managed, not a smart contract; each bounty should have its own user/wallet and signer.

## Execution and limitations

Every real submission checks the queue immediately before signing, compares the approved proposal with its saved fingerprint, and checks amount, destination, asset, chain, quote fees/output, payload digests and balance. Local Turnkey signing uses the buyer's explicit signer mapping, never the organization authentication key. The current Gateway market endpoint has no client slippage parameter; the adapter checks fresh prepared quote bounds and signs that exact payload. It does not claim a separate client-specified on-chain minimum-output guarantee. Limit buy-backs use an actual limit price.

Pay-in-kind proposal construction now checks unsigned transfer preparation for vendor minima and fees. The real test nevertheless returned a zero prepared fee and a 1 PYUSD settled fee. The router now checks net settlement and holds future execution on a mismatch. This after-settlement check cannot prevent the first inaccurate quote: **seller transfers remain held. Unsigned Solana transactions are now independently simulated and compared with the approved wallet debits and recipient credits before signing. Multi-transaction bridge bundles are rejected.** Do not treat the vendor's fee field as sufficient protection. The audited network fee was only 0.00001 SOL; the 1 PYUSD was a separate application transfer.

Private state is atomically persisted under `.runway/plans/`, with a process lock per proposal. Successful receipts can be reposted after queue delivery failure without paying again. Any uncertain submission stops blind retries; operation IDs and confirmed fills are retained for manual reconciliation. A partial swap is not rolled back if its later transfer fails. A quote expires; after 5 minutes, submit a fresh proposal for human approval. This local demo assumes one trusted machine and is not a distributed ledger or a substitute for server-side execution claims.
